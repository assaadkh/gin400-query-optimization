🧮 Course Formula & Cost Model Reference

Rigorous mathematical cost formulas for physical storage access and query execution.

Blocking & Spanning
File Geometry

$$bfr = \left\lfloor \frac{B}{R} \right\rfloor$$

$$b = \left\lceil \frac{r}{bfr} \right\rceil$$

Where $B$ is block size, $R$ is record size, $r$ is total table records.

Primary Index (Sparse)
Key Ordered File

$$b_I = \left\lceil \frac{b}{bfr_I} \right\rceil$$

$$\text{Cost} = \lceil \log_2 b_I \rceil + 1$$

1 anchor per data block. Binary search on index $+$ 1 data block fetch.

Clustering Index (Sparse)
Non-Key Ordered File

$$b_I = \left\lceil \frac{d}{bfr_I} \right\rceil$$

$$\text{Cost} = \lceil \log_2 b_I \rceil + \left\lceil \frac{s}{bfr} \right\rceil$$

$d$ distinct values. All matching records clustered sequentially.

Secondary Index (Dense)
Non-Ordering Candidate Key

$$b_I = \left\lceil \frac{r}{bfr_I} \right\rceil$$

$$\text{Cost} = \lceil \log_2 b_I \rceil + 1$$

One entry per record ($r$). Fast search, larger index file.

Multi-Level B+ Tree
Index Height & Fanout

$$fo = \left\lfloor \frac{B}{V + P_B} \right\rfloor$$

$$x = \lceil \log_{fo}(b_{i1}) \rceil + 1$$

Balanced search tree. Point lookup cost is strictly $x + 1$ block accesses.

Dynamic Hashing
Extendable Hash Table

$$\text{Dir Size} = 2^d$$

$$d' = d \implies d \leftarrow d + 1$$

Global depth $d$, local depth $d'$. Directory doubles only if $d' = d$.

Selection Algorithms
Linear & Binary Search

$$\text{Cost}(A_1) = \lceil b / 2 \rceil \text{ (Key)}$$

$$\text{Cost}(A_2) = \lceil \log_2 b \rceil$$

$A_1$ costs $b$ for non-key. $A_2$ requires physically ordered file.

Index Selection
Algorithms A3 - A6

$$\text{Cost}(A_3) = HT + 1$$

$$\text{Cost}(A_4) = HT + \lceil s / bfr \rceil$$

$$\text{Cost}(A_5) = HT + 1$$

$HT$ = Index height. $A_3$: Primary key eq, $A_4$: Clustering eq, $A_5$: Candidate key.

Join Algorithms
Nested-Loop Joins

$$\text{Simple NL} = b_R + b_R \cdot b_S$$

$$\text{Block NL} = b_R + \left\lceil \frac{b_R}{B - 2} \right\rceil \cdot b_S$$

$B$ = available memory buffers. Smaller relation should always be outer.

Sort-Merge Join
Sorted Relations

$$\text{Total Cost} = 3(b_R + b_S)$$

$$\text{Scan Only} = b_R + b_S$$

Sort phase costs $2(b_R + b_S)$, merge scan pass costs $b_R + b_S$.

Hash Join
Partition Hash Cost

$$\text{Cost} = 3(b_R + b_S) + b_{res}$$

$$M > \sqrt{b_{R} \cdot f}$$

Partitioning writes and reads $2(b_R + b_S)$, probing reads $b_R + b_S$.

Heuristics & Search Space
Plan Optimization

$$\sigma_\theta(R \bowtie S) \equiv (\sigma_\theta(R)) \bowtie S$$

$$\text{DP Search Complexity} = \mathcal{O}(3^n)$$

Selection & projection pushdown drastically reduces intermediate relation sizes.
